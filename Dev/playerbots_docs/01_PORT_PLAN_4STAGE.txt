A. CROSS-REFERENCE FINDINGS (cmangos engine  vs  OUR core) - verified this step
--------------------------------------------------------------------------------
 1) SPELL CASTING
    cmangos: builds `Spell* spell = new Spell(...)`; `spell->prepare(&targets)`
             with CMaNGOS SpellCastTargets; LookupSpellInfo via SpellEntry/DBC.
    OUR core (verified): Spell::prepare(SpellCastTargets const*, ...) EXISTS and
             takes the same shape; BUT preferred path is bot->CastSpell(target,
             spellId, args). SpellInfo via sSpellMgr->GetSpellInfo(id, Difficulty)
             - NOTE the extra Difficulty arg (use DIFFICULTY_NONE by default).
    => GOOD NEWS: closer than feared. Map LookupSpellInfo -> GetSpellInfo(id,
       DIFFICULTY_NONE); prefer bot->CastSpell over hand-building Spell objects.

 2) SPELL RANKS
    cmangos: relies on rank chains (highest known rank of a named spell).
    OUR core (verified): STILL has SpellChainNode / GetRank() / GetFirstRankSpell
             / GetNextRankSpell - so rank code won't BREAK, it just mostly no-ops
             on BfA (one spell per ability). => We can keep the rank plumbing as a
             thin pass-through and simplify later; not a hard blocker.

 3) TALENTS
    cmangos: TalentEntry/TalentTabEntry, points, tabs (WotLK).
    OUR core: SpecializationInfo + GetActiveTalentGroup + LearnTalent(talentId)
             + PvpTalents (BfA spec grid). => FULL REWRITE of Talentspec +
             Factory::InitTalents (the biggest single rewrite).

 4) MOVEMENT
    cmangos: MotionMaster MovePoint/MovePath + FORCED_MOVEMENT_* flags + Travel
             graph + mmaps.
    OUR core: MotionMaster MovePoint(id,x,y,z,generatePath)/MovePath/MoveSplineInit
             + PathGenerator + mmaps_generator. => Rewrite the move calls; map
             movement flags; Travel nodes rebuilt for 8.3 (start minimal).

 5) CORE HOOKS / BOT SESSION (the hard Phase-A piece)
    cmangos: one WorldSession per bot, driven by QueuePacket; PlayerbotMgr::
             UpdateSessions ticks them; OnPlayerLogin attaches master mgr.
    OUR core (verified): WorldSession ctor = (id, name, battlenetAccountId,
             shared_ptr<WorldSocket> sock, sec, expansion, ...). A bot session =
             pass a DUMMY/NULL socket + guard every socket send. Tick by hooking
             our World::Update (m_sessions loop) to also update bot sessions.

 6) YOUR WORK TO REUSE (high value)
    - Your DK (Blood/Frost/Unholy + DKActions/Triggers/Multipliers/Context) uses
      the SAME NamedObjectContext<Strategy> pattern as cmangos -> drops into the
      cmangos engine structure with minimal glue. = our class-content TEMPLATE.
    - Your Cata-Patch scaling features (BotActiveAlone, SmartScale,
      DisabledWithoutRealPlayer, AltBot auto-login, gear caps,
      EquipmentPersistence, MaintenanceStrategy, WaitForAttackStrategy) = mostly
      expansion-agnostic LOGIC -> fold into Stage 4.
    - Your Cata WorldHandlers/CharacterHandler.cpp = a worked example of the
      login/character core-integration edits -> reference for Phase A.
    NOTE: your repo has NO ServerFacade -> we take cmangos' facade as the seam,
      not yours; we take your CONTENT + features + integration know-how.
