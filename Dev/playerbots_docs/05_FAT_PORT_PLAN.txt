KEEP (already built + verified - they sit ABOVE the engine)
--------------------------------------------------------------------------------
 - modules/mod-psychobot packaging: loader, WorldScript tick, PlayerScript,
   CommandScript (.psychobot add/remove/list/spec/group), conf, cmake, README.
 - PsychobotMgr (registry of active bots, tick fan-out, commands).
 - PsychobotPopulationMgr (BotActiveAlone/SmartScale/DisabledWithoutRealPlayer).
 - PsychobotGroupMgr (party/roles/assist/heal-target).
 - PsychobotGearMgr (gear logic framework).
 - PsychobotAhBot (scaffold).
 - ai/PsychobotTalentMgr (generic BfA spec+talent application).
 These will call into the NEW engine (PsychobotAI gets a real AiObjectContext +
 engines instead of the thin ClassAI).

REPLACE (the thin engine + thin rotations)
--------------------------------------------------------------------------------
 - ai/PsychobotEngine.{h,cpp}        -> new fat Engine + Queue + ActionBasket.
 - ai/PsychobotClassAI.{h,cpp}       -> removed (engine drives class strategies).
 - ai/PsychobotClassRegistry.cpp     -> removed (per-class folders replace it).
 - ai/PsychobotStrategies.{h,cpp}    -> folded into generic/ strategies.
 - ai/PsychobotAI.{h,cpp}            -> rebuilt around the new engine + context.


NEW ENGINE LAYER (clean-room, TC 8.3) - the prerequisite for everything
--------------------------------------------------------------------------------
 src/engine/
   AiObject.h            base (ai*, bot, master) + relevance constants + threat.
   Action.{h,cpp}        Execute/isUseful/isPossible/P-A-C accessors.
   NextAction.{h,cpp}    {name,relevance} + array() builder.
   ActionNode.{h,cpp}    name + P/A/C arrays + ACTION_NODE_* macros.
   Value.h               Value<T>/CalculatedValue/MemoryCalculatedValue.
   Trigger.{h,cpp}       IsActive + handlers; TriggerNode.
   Multiplier.{h,cpp}    relevance scaling.
   Strategy.{h,cpp}      named; InitTriggers/InitMultipliers/GetDefaultActions.
   Queue.{h,cpp} + ActionBasket.{h,cpp}  relevance priority queue.
   NamedObjectContext.h  string->factory registry (+ Qualified parsing).
   AiObjectContext.{h,cpp}  composes Strategy/Action/Trigger/Value contexts.
   Engine.{h,cpp}        DoNextAction tick (ProcessTriggers->Queue->execute).
   ServerFacade.{h,cpp}  TC-8.3 core-API seam (expand our existing seam).


SHARED LIBRARIES (clean-room, only what class strategies need first)
--------------------------------------------------------------------------------
 src/values/   targets (nearest/attacker/CC/rti/assist), resources (hp/mana/
   rage/energy/runic/chi/fury), aura checks, distance, range, group, threat.
 src/triggers/ low health/mana, enemy in/out of melee, no aura, spell ready,
   target casting (interrupt), dispellable, has/needs buff.
 src/actions/  CastSpellAction (name->known spell via ServerFacade, BfA no-rank),
   melee, MoveTo/Chase/Flee/Follow/Reach, use item/potion, mount, loot, rti,
   stop/idle, follow master, attack, flee, etc.
 src/generic/  combat/non-combat shared strategies (follow, stay, dps, tank,
   heal-assist, ranged, melee, pull, dead/rez, threat).


CLASS FOLDERS (the bulk - one milestone each)
--------------------------------------------------------------------------------
 src/classes/<class>/  per class:
   <Class>AiObjectContext, <Class>Actions, <Class>Triggers, <Class>Multipliers,
   <Class>Strategy (shared) + per-SPEC strategies (ActionNodeFactory +
   InitCombatTriggers), reaction/noncombat/aoe as needed. 8.3 spell NAMES.
 Order: Death Knight (vertical slice) -> Warrior -> Paladin -> Hunter -> Rogue
   -> Priest -> Shaman -> Mage -> Warlock -> Druid -> Monk(new) -> DemonHunter(new).


MILESTONES (each = a self-contained, verifiable chunk)
--------------------------------------------------------------------------------
 M1  ENGINE CORE: AiObject/Action/NextAction/ActionNode/Value/Trigger/Multiplier/
     Strategy/Queue/ActionBasket/NamedObjectContext/AiObjectContext/Engine +
     expanded ServerFacade. (No behaviour yet; compiles, ticks empty.)
 M2  SHARED LIBS (minimum): core values/triggers/actions + generic combat/
     noncombat strategies (follow/attack/melee/cast/flee/rest). Rewire PsychobotAI
     to use AiObjectContext + engines. A bot follows + auto-attacks via the engine.
 M3  DEATH KNIGHT (full): DK context + actions/triggers/multipliers + Blood/Frost/
     Unholy strategies w/ real 8.3 rotations (procs/resources/CDs/AoE) + ghoul.
     VERTICAL SLICE proven end-to-end.
 M4-M13 remaining classes one per milestone (Warrior...DemonHunter), reusing the
     DK pattern; add Monk/DH net-new.
 M14 INTEGRATION: managers (population/group/gear/talent) wired to the new engine;
     PvP/BG + dungeon strategies; travel (minimal); ahbot; DbStore for saved
     strategies; hardening + Perf/Memory throttles.

 Each milestone: implement -> static verify (header/impl parity, includes, brace
 balance, API cross-ref) -> update Dev docs. Compile-verify happens once you have
 the toolchain + 8.3.7 client data (needed for spell-name->id + mmaps).
