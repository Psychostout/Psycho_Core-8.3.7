1. SCRIPT SYSTEM ENTRY POINTS
--------------------------------------------------------------------------------
 Header: src/server/game/Scripting/ScriptMgr.h
 - Every script is a subclass of one of the *Script base classes (below).
 - Construct it with a globally-UNIQUE name string: MyScript("module_my_script").
 - Register via a free function:  void AddSC_<name>() { new MyScript(); }
 - A module's loader (Add<module>Scripts) calls each AddSC_*.
 - Startup path: worldserver Main.cpp -> sScriptMgr->SetScriptLoader(AddScripts)
   -> ScriptMgr::Initialize() runs AddScripts() then AddModulesScripts().

4. PLAYER API  (src/server/game/Entities/Player/Player.h)
--------------------------------------------------------------------------------
 Identity/session:
   WorldSession* GetSession() const
   std::string GetName() const           ObjectGuid GetGUID() const

   bool AddItem(uint32 itemId, uint32 count)
 Teleport / position:
   bool TeleportTo(uint32 mapId, float x, float y, float z, float o, ...)
   (also TeleportTo(WorldLocation const&, ...))
 Spells / talents (THIS is the BfA talent model - NOT 3.3.5 talent points):
   bool HasSpell(uint32 spell) const
   void LearnSpell(uint32 spellId, bool dependent, int32 fromSkill=0, ...)
   void RemoveSpell(uint32 spellId, bool disabled=false, bool learnLowRank=true, ...)

   SpecializationInfo _specializationInfo (ResetTalentsCost/Time, ActiveGroup)
 Persistence:
   void SaveToDB(bool create=false)
 NOTE: BfA uses specialization + PvP talents + class talents stored per spec;
       there is no "free talent point" economy like WotLK. Use LearnTalent/
       ResetTalents and the SpecializationInfo, not 3.3.5-era talent-point APIs.

11. SPELLS / SPELLINFO / SPELLSCRIPT
--------------------------------------------------------------------------------
 SpellInfo: sSpellMgr->GetSpellInfo(spellId, DIFFICULTY_NONE)
   (src/server/game/Spells/SpellInfo.h, SpellMgr.h). 8.3 spells are keyed by
   (id, Difficulty) - always pass a Difficulty.
 SpellScript / AuraScript (src/server/game/Spells/Auras/ + Spells/):
   Hook handlers (OnEffectHitTarget, OnCast, OnHit, DoCheckCast, OnApply/OnRemove
   for auras). Register via SpellScriptLoader::GetSpellScript()/GetAuraScript().
 DBC/DB2 data: src/server/game/DataStores/DB2Stores.h (sSpellNameStore, etc).


12. DATABASE ACCESS FROM A MODULE
--------------------------------------------------------------------------------
 Pools: WorldDatabase, CharacterDatabase, LoginDatabase (and HotfixDatabase).
   QueryResult r = WorldDatabase.Query("SELECT ...");
   WorldDatabase.Execute("UPDATE ...");
   Prepared statements + async via CharacterDatabase.AsyncQuery(...).
 Config: sConfigMgr->GetBoolDefault/GetIntDefault/GetStringDefault/GetFloatDefault
   (src/server/shared/... Config). Module conf keys live under [worldserver].
 Logging: TC_LOG_INFO/ERROR/DEBUG("module.<name>", "...", args)  (Log.h).
 Module SQL auto-apply: insert into the DB's `updates_include` table a row
   ('$/modules/mod-<n>/sql/<db>', 'MODULE') OR drop files in sql/custom/<db>/.


13. GAPS / "DID I MISS ANYTHING?" CHECKLIST  (things module authors also need)
--------------------------------------------------------------------------------
 Important areas NOT to forget (present in this core; explore as needed):
  [ ] RBAC permissions for commands  -> src/server/game/Accounts/RBAC.h
  [ ] Localization / string entries  -> trinity_string table + GetTrinityString
  [ ] Achievements/Criteria scripts  -> AchievementCriteriaScript
  [ ] Conversations & Scenes (BfA)   -> ConversationScript, SceneScript
  [ ] PlayerChoice (BfA UI choices)  -> PlayerScript::OnPlayerChoiceResponse
  [ ] AreaTrigger entities (BfA)     -> AreaTriggerEntityScript / AreaTriggerAI
  [ ] Battlegrounds/Arena & OutdoorPvP-> BattlegroundScript / OutdoorPvPScript
  [ ] Guild/Group hooks              -> GuildScript / GroupScript
  [ ] Vehicles                       -> VehicleScript
  [ ] Transports / paths             -> TransportScript + spline chains
  [ ] Phasing (PhaseShift)           -> PhasingHandler (src/server/game/Phasing)
  [ ] Garrison/Scenario (Legion/BfA) -> src/server/game/... (if your module needs)
  [ ] Hotfix DB2 data (BfA client)   -> hotfixes DB + DB2Stores
  [ ] Anti-cheat / movement validation considerations for custom teleports
  [ ] Threading: scripts run on the world/map update thread - avoid blocking;
      use AsyncQuery + TaskScheduler. Dynamic modules can be hot-reloaded, so
      don't hold raw pointers across reloads.
  [ ] Save/persistence: custom per-character data -> own table in characters DB.
