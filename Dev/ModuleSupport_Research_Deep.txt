2. HOW THE SCRIPT/MODULE BUILD ACTUALLY WORKS (verified in this repo)
--------------------------------------------------------------------------------
 src/server/scripts/CMakeLists.txt does, per module dir:
   - linkage = SCRIPTS_<MODULE> (dynamic | static | disabled), default from
     SCRIPTS=dynamic/static; "minimal" uses a whitelist (Commands, Spells).
   - DYNAMIC: CollectSourceFiles -> ConfigureScriptLoader(...ON...) -> generate
     gen_scriptloader/<mod>/ScriptLoader.cpp -> add_library(<proj> SHARED ...)
        target_link_libraries(<proj> PRIVATE trinity-core-interface PUBLIC game)
        install to ${INSTALL_OFFSET} (= <prefix>/bin/scripts on unix).
   - STATIC: sources appended to PRIVATE_SOURCES; module name -> STATIC list.
   - At end:
        ConfigureScriptLoader("static" ... OFF ${STATIC_SCRIPT_MODULES})
        add_library(scripts STATIC ScriptLoader.h <static-loader> ${PRIVATE_SOURCES})
        set(WORLDSERVER_DYNAMIC_SCRIPT_MODULES_DEPENDENCIES ... PARENT_SCOPE)
 worldserver/CMakeLists.txt then:
        target_link_libraries(worldserver PUBLIC scripts game readline ...)
        add_dependencies(worldserver ${WORLDSERVER_DYNAMIC_SCRIPT_MODULES_DEPENDENCIES})

 The generated loader (ScriptLoader.cpp.in.cmake) defines:
   - AddScripts() that calls each Add<Module>Scripts();
   - when dynamic: also exports GetScriptModule/GetScriptModuleRevisionHash/
     GetBuildDirective via extern "C" (THIS is what enables HOT RELOAD via
     src/server/game/Scripting/ScriptReloadMgr.cpp).

 KEY: a "module" only needs to provide a function:
        void Add<ModuleName>Scripts();
   ...which calls its AddSC_* registrators. Everything else is generated.

         mod_example.cpp            # PlayerScript/WorldScript + AddSC_mod_example()
         mod_example_loader.cpp     # void AddmodexampleScripts(){ AddSC_mod_example(); }

 NOTE on loader-fn naming: ConfigureScriptLoader builds "Add${MODULE}Scripts()"
 from the directory name. AC strips '-' to '_' (string(REGEX REPLACE - _ ...)).
 THIS repo's ConfigureScriptLoader does NOT strip '-'. So either:
   (a) name module dirs without '-' (e.g. modexample), or
   (b) add the same REGEX REPLACE to our modules loader (recommended; keeps the
       familiar mod-<name> convention).

5. MODULE SQL - HOW IT GETS APPLIED (verified)
--------------------------------------------------------------------------------
 The DB auto-updater (src/server/database/Updater/UpdateFetcher.cpp) does NOT
 hardcode SQL paths. It reads directories from the DB table `updates_include`:
     SELECT `path`, `state` FROM `updates_include`
 then FillFileListRecursively() scans each path recursively. A leading "$"
 in path is replaced with the SourceDirectory.

 => TWO ways to auto-apply module SQL (no core C++ change either way):
   (A) EASIEST: tell users to drop module SQL into the already-registered
       sql/custom/{world,characters,auth,hotfixes} dirs (these are pre-listed in
       updates_include in the base auth DB). Works immediately.
   (B) PROPER: have each module ship sql/<db>/... and INSERT a row into
       `updates_include` (e.g. '$/modules/mod-x/sql/world','MODULE') so the
       updater scans it. AC effectively does (A)/(B)-style via data/sql/custom.
 Requires: Updates.EnableDatabases=15 (already set) + Updates.AutoSetup=1
           (already 1) + a valid SourceDirectory at runtime.


6. C++ API COMPATIBILITY (BfA 8.3 vs AC WotLK 3.3.5)
--------------------------------------------------------------------------------
 - The MODULE FRAMEWORK (cmake glue, loader generation, hot reload) is core-
   version-agnostic and ports cleanly. CONFIRMED by structural match.
 - INDIVIDUAL module SOURCE is NOT portable: existing AC `mod-*` repos target
   WotLK 3.3.5 APIs and will NOT compile on this BfA 8.3 core unchanged
   (different ScriptMgr hooks, signatures, opcodes, DB2 vs DBC, etc.).
   => Our mod-example must be written against THIS repo's ScriptMgr API
      (e.g. class X : public PlayerScript { ... }; void AddSC_x(){ new X(); }).
 - Script base classes/hooks available are whatever src/server/game/Scripting/
   ScriptMgr.h exposes in this 8.3 tree (to be enumerated in Step 8).
