3) THE REPEATABLE PER-CLASS PATTERN (how every class was built - reuse it)
--------------------------------------------------------------------------------
 For class X with specs [s0,s1,s2(,s3)], create modules/mod-psychobot/src/
 classes/<x>/ with THREE units:
 (a) <X>Triggers.{h,cpp}: class-specific conditions the rotation keys off. Each
     trigger READS core VALUES BY NAME via the context, e.g.:
        ctx->GetValue<float>("power", std::to_string(POWER_xxx))   // resource %
        ctx->GetValue<bool>("has aura", "Spell Name")              // self aura
        ctx->GetValue<bool>("target has aura", "Spell Name")       // target aura
        ctx->GetValue<bool>("spell ready", "Spell Name")           // known+offCD
     Register via NamedObjectContext<Trigger> in RegisterXTriggers().
 (b) <X>Strategies.{h,cpp}: GenericXStrategy base + one Strategy per spec +
     GenericXNonCombatStrategy. Spec strategies override GetDefaultCombatActions()
     (the spell PRIORITY list) and InitCombatTriggers(list&). Wire with:
        triggers.push_back(new TriggerNode("trigger name",
            NextAction::Array(1, new NextAction("cast melee::Spell Name", REL),
                              nullptr)));
     ALL casting goes through the keystone family BY NAME (no per-spell C++):
        "cast::Frostbolt", "cast melee::Mortal Strike", "cast heal::Holy Shock",
        "cast self::Recklessness", "cast melee aoe::Whirlwind", "cast buff::...",
        "cast dispel::...", "cast pet::...". Register via RegisterXStrategies().
 (c) <X>AiObjectContext.{h,cpp}: namespace X { RegisterContext(ctx) calls the two
     registrars; CombatStrategyForSpec(specIndex) maps 0/1/2(/3) -> strategy name }.
 (d) WIRE into ai/PsychobotAiFactory.cpp (3 spots): RegisterContext case;
     InitCombatEngine AddStrategy("<x>") + AddStrategy(CombatStrategyForSpec);
     InitNonCombatEngine AddStrategy("<x> nc").
 Per-bot contexts are class-scoped, so duplicate strategy NAMES across classes are
 fine (e.g. "protection" for Warrior AND Paladin; "frost" for DK AND Mage).


4) HOW THE ENGINE TICKS
--------------------------------------------------------------------------------
 PsychobotMgr::UpdateAI -> PsychobotAI::UpdateAI (throttled ~250ms) ->
 EnsureSpecAndTalents (applies BfA spec, rebuilds combat engine) -> pick Engine
 by state -> Engine::DoNextAction():
   1. (re)collect triggers/multipliers from active strategies
   2. ProcessTriggers: active trigger pushes its NextAction[] into the Queue
   3. PushDefaultActions: each strategy's defaults into the Queue
   4. pop highest-relevance basket -> resolve ActionNode -> bind Action from the
      context -> apply multipliers -> if useful+possible, run prerequisites first
      ("reach melee"/"reach spell"), else Execute; queue continuers; return.
 Names resolve to the spell the bot knows via PsychobotAI::GetSpellIdByName
 (case-insensitive). DB2-agnostic: an unknown name just no-ops that one ability.
 Relevance (engine/AiObject.h): IDLE=1 NORMAL=10 HIGH=20 MOVE=30 INTERRUPT=40
 DISPEL=50 LIGHT/MEDIUM/CRITICAL_HEAL=60/70/80 EMERGENCY=90 PASSTHROUGH=100.
